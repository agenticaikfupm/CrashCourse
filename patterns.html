Agent Design Patterns

Design patterns are reusable ways to arrange model calls, tools, and checks. Start with the simplest pattern that solves the problem, and add autonomy only when it clearly helps.

Narration:

Workflows and agents

A helpful distinction, used for example in Anthropic's engineering article "Building effective agents":

  • Workflows follow paths that you define in code. The model fills in the steps, but the order is fixed. They are predictable and easy to test.
  • Agents let the model decide the path: which tool to call, when to loop, and when to stop. They are flexible but harder to predict, more expensive, and need stronger guardrails.

The patterns below move roughly from low to high agency (how much the model decides on its own). The course slides mark agency level as an open question for each pattern, so the bars here are an illustrative rating by the course team, meant for discussion.

Basic responder

Agency level (illustrative) 1 of 5

One prompt, one model call, one answer. This is the baseline every other pattern improves on.

Strengths

  • Fastest and cheapest
  • Simple to build and test

Limitations

  • No access to current or private data
  • No verification, so it can state invented facts

Suitable use cases

  • Rewriting, summarizing, brainstorming
  • Questions about general knowledge

Example from the slides: "Please suggest recent books on smart mobility." The model returns a list of titles, but nothing checks that they exist. A search tool (tool calling pattern) fixes this.

Sequential workflow (prompt chaining)

Agency level (illustrative) 2 of 5

Split a task into fixed steps where each step's output feeds the next. Add programmatic "gates" between steps to stop early when something is wrong.

Strengths

  • Each step is simpler, so quality is higher
  • Easy to debug: inspect every intermediate result
  • Predictable cost and latency

Limitations

  • Slower than a single call
  • Errors in early steps propagate
  • Cannot adapt the order to unusual inputs

Suitable use cases

  • Draft, then translate, then format
  • Extract data, validate it, then write a report

Routing

Agency level (illustrative) 2 of 5

A router classifies each input and sends it to the best handler: a specialized prompt, a different model, or a tool. The slides show a router LLM choosing between an image model and two LLM routes.

Strengths

  • Specialized handlers do better than one general prompt
  • Saves cost: send easy requests to small models

Limitations

  • A wrong classification sends the request down the wrong path
  • Routes must be kept in sync as the system grows

Suitable use cases

  • Customer support triage
  • Choosing text, image, or code models
  • Small model for easy questions, large model for hard ones

Parallel execution

Agency level (illustrative) 2 of 5

Run independent subtasks at the same time and combine the results. Sectioning gives each worker a different part; voting runs the same task several times and compares answers.

Strengths

  • Lower total latency
  • Each worker can focus on one aspect
  • Voting improves confidence

Limitations

  • Only works when subtasks are independent
  • More calls means more cost
  • Merging conflicting results needs care

Suitable use cases

  • Reviewing a document for several criteria
  • Running a guardrail check alongside the main answer
  • Searching several sources at once

Tool calling

Agency level (illustrative) 3 of 5

The model chooses tools and arguments, sees each result, and continues until the task is done. The slides list typical tools: APIs, a browser, a vector database, the local file system, and an optimization solver.

Strengths

  • Access to current, private, and exact information
  • Can take real actions
  • Results are grounded in tool outputs

Limitations

  • Wrong arguments or tool choice cause errors
  • Side effects need permissions and confirmation
  • Tool outputs can carry prompt-injection text

Suitable use cases

  • Email and calendar assistants
  • Data lookups and calculations
  • Booking and ticketing systems

Example from the slides: "Filter my emails by importance and send an out-of-office notification to the top 5 most important emails", with a confirmation step before sending.

Evaluator-optimizer (reflection) loop

Agency level (illustrative) 3 of 5

One call generates, another evaluates and gives feedback, and the generator revises. The slides call this the reflection pattern: generate, reflect, iterate, then return the reflected output.

Strengths

  • Noticeably better quality when clear criteria exist
  • Tests or rubrics make the evaluation objective

Limitations

  • Several rounds multiply cost and time
  • A model may approve its own mistakes
  • Needs a stopping rule

Suitable use cases

  • Code generation with unit tests
  • Translation or writing with a style rubric
  • Search that must reach a quality bar

Plan-and-execute

Agency level (illustrative) 4 of 5

A planner writes the whole plan first; an executor carries out each step with tools; a replanner adjusts the remaining steps when something fails. A close relative is the orchestrator-workers pattern, where a central model hands steps to worker models.

Strengths

  • Handles long, multi-step tasks
  • The plan is visible and can be reviewed by a person
  • Recovers from failures by replanning

Limitations

  • A bad plan wastes every later step
  • Plans can go stale as the situation changes
  • Harder to test than fixed workflows

Suitable use cases

  • Research tasks across several sources
  • Data analysis pipelines
  • Multi-step operations with approvals

Multi-agent collaboration

Agency level (illustrative) 5 of 5

Several agents with different roles, prompts, or tools work together, usually coordinated by a manager agent. The slides name three cooperation styles:

  • Augmentative: each agent adds a different piece (division of labor).
  • Integrative: outputs are merged into one consistent result.
  • Debative: agents critique each other until they converge.

Strengths

  • Separation of concerns: each agent stays focused
  • Debate can catch errors a single agent misses
  • Teams can scale to large tasks

Limitations

  • Highest cost and latency
  • Coordination failures and loops
  • Harder to trace who decided what

Suitable use cases

  • Complex reports needing research, analysis, and review
  • Software projects with planner, coder, and tester roles
  • Simulations with several stakeholders

Choosing a pattern

Quick guide for choosing a design pattern
If your task...Start with
can be answered in one step from general knowledgeBasic responder
always follows the same stepsSequential workflow
has clearly different kinds of inputRouting
has independent parts, or benefits from several opinionsParallel execution
needs current data or must change somethingTool calling
has clear quality criteria or testsEvaluator-optimizer
is long and its steps are not known in advancePlan-and-execute
needs several distinct skills or viewpointsMulti-agent
Patterns combine

Real systems mix patterns: a router may send hard requests to a plan-and-execute agent whose steps use tools and whose final answer passes through an evaluator.
