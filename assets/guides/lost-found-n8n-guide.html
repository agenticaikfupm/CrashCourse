Before you start

You will need:

  • An n8n workspace with Data tables, AI Agent and Guardrails nodes.
  • A Chat Model node and API credential for your chosen model provider. Select a model with tool calling and structured output support.
  • A Telegram account and access to BotFather to create your bot.

How to use this guide:

  • Keep this page beside n8n. Use Copy to paste each block into the named field.
  • Use Expression mode for {{ … }} values and fixed text for prompts and labels.
  • Orange outlines identify the current stage. Expand any diagram for a closer view.
  • Mark a stage complete after its checkpoint passes.

Build the conversational shell

Connect a chat trigger, language model and conversation memory.

Follow these steps

  1. Create a new workflow. Add When chat message received and connect it to an AI Agent. Keep the name AI Agent exactly; later expressions reference it.
  2. From the Agent’s Chat Model connector, add the Chat Model node for your chosen provider. Select its credential and a model that supports tool calling.
  3. From the Memory connector, add Simple Memory. For this chat test, use the session ID from the connected Chat Trigger.
  4. Set the Agent’s user prompt source to Define below and paste the user message expression. You will add the complete system message in stage 4.
  5. Open the n8n chat panel and send a greeting, then a second message. Keep this trigger for the early tests; Telegram becomes the active entry point in stage 6.

Give the agent a search tool

Let the agent retrieve available found-item records.

Follow these steps

  1. Click the AI Agent’s Tool connector and add a Data Table tool with the Get row(s) operation.
  2. Rename it Search Found Items and select your found items table.
  3. Add the condition status equals Available. Enable Return All for this small dataset.
  4. Keep the tool connected and send the search test below. Stage 4 supplies the complete system message for the lost-and-found conversation.
  5. Send the test message, then open the execution to inspect the tool request and returned rows.

Stage 4 of 97 min

Add the operating instructions

Define how the assistant searches, asks questions and handles claims.

Follow these steps

  1. Open AI Agent → Options → System Message.
  2. Copy the complete system message below and paste it into the field.
  3. Read the search rules and claim process. The claim instructions become usable when the Submit Claim tool is added in stage 5.
  4. Start a fresh chat session and test a vague description, a specific description and an inventory request.
AI Agent system message · Fixed text
Read the full prompt · 53 lines
You are a lost-and-found assistant. Help users identify possible matches from the available found-item records.

If the user sends /start or a general greeting, briefly introduce yourself as a lost-and-found assistant and ask them to describe the item they lost.

Follow this process:

1. Collect useful details about the lost item:
   - category or item type
   - color
   - brand, if known
   - possible location
   - approximate date
   - distinguishing features known by the user

2. Ask one focused, open-ended question at a time when information is missing. Do not suggest possible answers or give examples that could help the user construct a matching description.

3. If the user provides enough information to begin searching, call the Search Found Items tool.

4. Compare the user’s description with the returned records. Consider category, color, brand, location, date, and distinguishing features.

5. If several records are plausible, ask an open-ended question that would best distinguish between them. Do not mention the candidates or reveal their details.

6. If one record appears plausible, provide its item ID and relevant recorded details. Explain which details match the user’s description. State that it is only a possible match and that ownership still needs to be verified. Ask whether the user wants to file a claim.

7. If no record is suitable, say that no likely match was found. Invite the user to correct or add information without suggesting what that information should be.

Rules:

- Do not invent records or item details.
- Use only information returned by the tools.
- Do not list, count, summarize, or offer access to the current found-item inventory.
- Do not reveal multiple item records or possible matches.
- Do not provide item details before the user has described a specific lost item with enough information for a reasonable match.
- You may provide the item ID and relevant details of one plausible match so the user can decide whether to file a claim.
- Do not suggest brands, colors, models, locations, dates, or distinguishing features to the user.
- Do not reveal a distinguishing feature that should be reserved for ownership verification.
- Do not claim that an item belongs to the user.
- Ask only one follow-up question at a time.
- Keep responses concise and conversational.

Claim submission process:

- Submit a claim only after identifying one plausible item.
- Ask whether the user wants to file a claim for that item.
- Collect the claimant’s name, contact information, and ownership details.
- The ownership details must come independently from the claimant and must not merely repeat information disclosed from the found-item record.
- Do not suggest possible ownership details.
- Summarize the proposed claim and ask the user to confirm it before submission.
- Do not call the Submit Claim tool until the user explicitly confirms.
- After submission, return only the new claim ID and status.
- Never retrieve, list, summarize, or reveal existing claims.
- Never reveal claimant information.
- Never invent missing claim information.
The highlighted node is being configured in this stage; no new canvas node is added. The output privacy check in stage 7 provides a separate check on the final reply.

Check before continuing

A vague description should lead to one focused question. A specific description may produce one possible match. An inventory request should receive a refusal.

Connect Telegram and send a reply

Give the agent a working Telegram conversation channel.

Follow these steps

  1. Create a bot with BotFather in Telegram. Save the token in an n8n Telegram credential.
  2. Add Telegram Trigger, select that credential, and choose Message updates.
  3. Add Edit Fields after the trigger. Name it Prepare Telegram Message and add the String fields below.
  4. Switch the workflow input to Telegram: disconnect the Chat Trigger from the Agent and connect Prepare Telegram Message to AI Agent. Keep the Agent’s prompt as {{ $json.chatInput }}. The disconnected Chat Trigger can stay on the canvas for testing.
  5. Open Simple Memory, choose a manually defined session key and use {{ $json.sessionId }}.
  6. After the Agent, add Telegram → Send Message and name it Reply Approved. Set Chat ID and Text using the expressions below. Use the same Telegram credential.
  7. Listen for a Telegram test event and send /start. Keep the workflow unpublished during manual trigger testing. This guide uses text messages.

Stage 7 of 97 min

Add an output privacy check

Review the proposed reply before Telegram receives it.

Follow these steps

  1. Remove the direct connection from AI Agent to Reply Approved. Insert Guardrails after the Agent and name it Check Text for Violations.
  2. Select Check Text for Violations. Set Text to Check to {{ $json.output }}. Add one Custom guardrail named Inventory and claims privacy.
  3. Paste the custom prompt below and set its threshold to 0.95. Attach a second Chat Model node for your chosen provider; use a model that supports the guardrail’s structured response.
  4. Connect Pass to the existing Reply Approved. Its Text must reference AI Agent directly, using the approved expression below.
  5. From Fail, add an Edit Fields node named Safe Refusal. Add a String field named output containing the safe refusal text.
  6. Connect Safe Refusal to a second Telegram → Send Message node named Reply Blocked. Use the same Chat ID expression and set Text to {{ $json.output }}.

Custom guardrail prompt · Fixed text
Read the full prompt · 26 lines
Evaluate only whether the assistant response clearly exposes multiple private lost-and-found records or existing claim records.

Flag the response only when it clearly does one or more of the following:

- Reveals two or more found-item records or possible matches.
- Lists, counts, summarizes, exports, or offers access to the found-item inventory.
- Reveals a list of existing claims.
- Reveals information from an existing claim belonging to another person.
- Reveals another claimant’s name, contact information, or ownership evidence.
- Gives instructions for accessing, enumerating, exporting, or bypassing restrictions on item or claim records.

Do not flag the response when it:

- Asks any question needed to understand the user’s lost item.
- Requests the item type, color, brand, location, date, or distinguishing features.
- States that no suitable match was found.
- Presents one possible matching item, including its item ID, category, color, brand, location, date, description, and match explanation.
- Asks whether the user recognizes the possible match.
- Asks whether the user wants to file a claim for one possible match.
- Collects the user’s name, contact information, or ownership evidence for a new claim.
- Summarizes a new claim created during the current conversation.
- Provides the ID and status of a newly submitted claim.
- Explains the lost-and-found process without exposing multiple records.
- Refuses a request for inventory or claim information.

When uncertain, do not flag the response. A response about one possible matched item is permitted. Trigger a violation only for clear bulk disclosure or disclosure of another person’s existing claim.

Test the full conversation

  1. Start a new Telegram test conversation. To isolate old memory, change the session prefix to a new value in Prepare Telegram Message.
  2. Send the messages below one at a time. Follow the Agent’s actual questions; provide any still-missing detail before confirming.
  3. After the search and claim turns, open the execution and inspect Search Found Items and Submit Claim.

Stage 9 of 93 min

Publish and verify the bot

Run your completed workflow outside manual test mode.

Follow these steps

  1. Restore the normal guardrail Text to Check expression if you changed it for the synthetic test.
  2. Stop manual Telegram trigger testing. Save the workflow and publish or activate it, depending on your n8n version.
  3. Send /start to the bot, then try a complete item search and claim flow.
  4. Check the production execution and new claim row. Test from a second Telegram account if available to verify separate chat histories.

The bot uses an old conversationCheck the session key. A new prefix starts a separate history; it does not delete earlier memory.
