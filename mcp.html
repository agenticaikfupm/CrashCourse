Model Context Protocol (MCP)

MCP is an open standard for connecting AI applications to external tools and data. Build a connector once as an MCP server, and any MCP-compatible application can use it.

Narration:

What MCP is

The Model Context Protocol was introduced by Anthropic in November 2024 as an open protocol. It defines how an AI application asks an external program what it can do (its tools, data, and prompt templates) and how it uses those capabilities. Messages follow JSON-RPC 2.0, a simple request and response format. The official documentation compares MCP to a USB-C port: one standard connector instead of a custom cable for every device.

Why it is useful

Build once, reuse everywhere

Without a standard, every app needs its own integration for every system. With MCP, one server for your database works in any MCP-compatible host.

Clear boundaries

The server holds credentials and business logic. The model only sees tool descriptions and results, and the host can ask the user before each call.

Shared ecosystem

Open-source and vendor servers exist for common systems such as file systems, Git hosting, databases, and browsers, so you rarely start from zero.

Hosts, clients, and servers

Host

The AI application the user works in, such as a chat app, an IDE, or your own agent. It runs the model and manages permissions.

Client

A connector inside the host. Each client keeps a one-to-one connection with one server.

Server

A program that exposes capabilities. It can run locally (started by the host, talking over stdio) or remotely (over Streamable HTTP).

Clients can offer features to servers too, such as sampling (a server asks the host's model to generate text). See the specification for the full list.

How MCP connects agents to external systems

The model never talks to the database or API directly. It only requests a tool call. The host decides whether to allow it, the client sends it to the right server, and the server, which you control, performs the real operation with its own credentials and validation. This separation is what makes MCP integrations reusable and easier to secure.

Try it: MCP messages and a real server

Example 1 simulates both sides in one program so you can read the actual JSON-RPC messages. Input: five client requests. Output: each request and the server's reply. It is a simplification for learning and skips transport and parts of the handshake.

Example 2 uses the official Python SDK (version 2). The MCPServer class (named FastMCP in version 1 of the SDK) turns decorated Python functions into a tool, a resource, and a prompt. A client then starts the server as a subprocess and calls it. It needs the mcp package, so run it in Colab or locally; the notebook writes the server file and runs the client for you.

Test your server visually

The official MCP Inspector is a browser-based tool for connecting to a server, listing its capabilities, and calling tools by hand.

Using MCP safely

  • Trust: only install servers from sources you trust. A server runs code on your machine or sees your data.
  • Least privilege: give each server the minimum access it needs, for example a read-only database user.
  • Consent: keep user approval on for tools that change data, send messages, or spend money.
  • Untrusted content: tool results and descriptions can contain hidden instructions (prompt injection). Treat them as data.
